# Visual UI — Air prototype, 2026-10-07

Open `Launch Visual Playroom.command` at the repository root. It builds and opens the native Mac prototype using its own `.prototype-build/visual-interactive/personality.json`, keeping synthetic verification rituals out of interactive memories. The already-built app is `.prototype-build/Build/Products/Debug/Fonsters.app`. Choose a portrait on the left, touch the fluffy creature, and use the three-person icon to enter its local world.

## Design

The creature/world leads. Portraits replace creature lists; routine actions use 44-point icon targets; related actions share space and tint: mint for touch/company, peach for play, lavender for world/curiosity, neutral for sensors/motion. A checkmark and border indicate selection alongside color. Controls keep native buttons, keyboard focus, tooltips, accessibility labels, and native toggle accessibility representations. H/P/R/B/L and Space remain available; action shortcuts suspend while a typed request has focus. The text-bubble icon reveals the existing typed request field.

The pass covers the Mac Playroom, personality popover, local lobby, world toolbar, agent studio, local social studio, command bar, and visit share/review sheets. Names, actual user input, actual draft content, errors, explicit reflection/audience choices, publishing choices, and recipient-retention disclosure retain meaningful text. Additional descriptions/source/privacy details are available from information icons. Draft text stays visible before approval; approved local moments can reveal their caption on demand. The publishing radio choices show **Review each draft** and **Post locally** in full. No simulated followers, reactions, or social metrics were introduced.

This does not redesign the production iOS seed editor or port the 3D world to iOS. Existing 2D appearance/exports/seed links, stored appearance identity, personality models, agent scopes, local publishing policy, permission requests, and pause/Reduce Motion/background/Low Power gates are preserved. External agents and public-platform accounts are still unconnected; the local director runs only while its existing gates allow it.

The requested audio-worker handoff is [sound-effects-brief.md](sound-effects-brief.md): exact current filenames, voices, proposed future events, output specifications, provenance, and playback requirements. No paid generation, upload, account creation, or new software installation was used for this pass.

## Capture provenance

AppKit's own-window bitmap omits Metal surfaces. `--window-export-target` selects the intended view, preventing restored windows from overwriting a different screen's evidence. For Playroom/lobby, `--ui-scene-photo` adds a genuine RealityKit GPU render cloned from that window's live entities/camera, composited into the stage's measured rectangle. These are **app-owned UI/scene composites**, not desktop screenshots or generated concept art. Agent Studio is an AppKit own-window capture. The social photo is the existing genuine one-time native GPU profile render displayed as an NSImage.

`evidence/visual-ui/native-touch-poses.mp4` is a short silent clip assembled from seven actual native held/settled pose captures in the final passing replay. It is sampled pose evidence, not continuous desktop recording; frame dwell follows measured capture times with gaps capped at two seconds. `evidence/responsive-touch-demo.mp4` is the prior 9.833-second sampled native gesture demonstration; its renderer/touch implementation remains unchanged by this UI pass. No camera, microphone, desktop, or other app content was recorded. Build products, screenshots, clips, and verification archives stay ignored by Git.
